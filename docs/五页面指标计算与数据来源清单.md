> 覆盖页面：`#/kpi-checklist`、`#/indicator-overview`、`#/path1`、`#/path2`、`#/path3`
> 表格列：`指标 | 后端函数 | 计算过程 | 数据来源 | 字段 | 是否ERP数据`
> 字段命名：`字段英文（中文含义）`，ERP 字段中文见「ERP 物料凭证清单 MB51」；WMS 字段中文见 `v_project_inventory_wide` 视图字段说明。

## 〇、通用口径（先记住这 3 个 WMS 金额公式）

所有「否 ERP」的指标都来自 WMS 视图 `v_project_inventory_wide`，三个核心金额在 `backend/utils.py` 统一定义：

- **入库金额** `inbound_amount` = `original_quantity`（原始入库数量）× `unit_price`（当前加权均价）
- **领用金额** `claimed_amount` = `total_outbound_quantity`（累计出库数量）× `unit_price`（当前加权均价）
- **库存金额** `inventory_amount` = `total_price`（当前库存价值）= Σ(`current_quantity`（当前库存数量）× `unit_price`)

> 关键点：视图 `v_project_inventory_wide` 是「批次 × 项目」N 行膨胀结构，所有聚合必须先 `DISTINCT ON (tenant_id, material_code, batch_code, erp_inventory)` 按物理批次去重，再按 `project_ratio`（项目当前库存数量占比）分配到项目。

### ERP 口径（`是否ERP数据 = 是` 的来源）

- `public.erp_catalog_mb51`：ERP 物料凭证清单（MB51），工厂 `werks`（工厂）='2635'
  - 移动类型 `bwart`（移动类型）：入库 `101`(收货)、`102`(冲销，负数)；出库 `201`(成本中心)、`221`(项目)、`222`、`Z61`(项目)、`Z62`
  - 金额 `row_json->>'DMBTR'`（以本币计的金额）、数量 `row_json->>'MENGE'`（数量）、凭证日期 `row_json->>'BLDAT'`（凭证日期，取前 4 位作年份）、物料 `row_json->>'MATNR'`（物料）、批次 `charg`（批次）
- `v_batch_lifecycle`：批次生命周期视图，关键字段 `best_inventory_amt`（最佳估计库存金额）

## 〇·二、`v_project_inventory_wide` 视图的底层数据链路（视图 → 源表）

「否 ERP（WMS）」指标的数值都来自视图 `v_project_inventory_wide`。这个视图本身不是物理表，而是由 **5 张源表** JOIN 出来的（定义见 `backend/sql/01_v_project_inventory_wide_optimized.sql`）。再往下追一层：

```
v_project_inventory_wide
├─ inv_agg（主表）＝ wms_inventory 按 (tenant_id, material_code, batch_code, erp_inventory) 聚合
│     过滤：del_flag='0' AND warehouse_code='A00' AND status=1
├─ LEFT JOIN wms_project_inventory   （项目台账）     关联键：四字段 + del_flag='0'
├─ LEFT JOIN dim_material_cache      （物料维度缓存） 关联键：material_code
├─ LEFT JOIN dim_project_cache       （项目维度缓存） 关联键：project_code = owner_project_code
└─ LEFT JOIN dim_outbound_log_cache  （出库日志缓存） 关联键：四字段
```

### 5 张源表的最终来源

| 视图里 JOIN 的表 | 最终源头 | 是否 ERP |
|---|---|---|
| `wms_inventory`（物理库存，主表） | WMS 库存表（原表） | ❌ WMS |
| `wms_project_inventory`（项目台账） | WMS 项目库存表（原表） | ❌ WMS |
| `dim_material_cache`（物料维度） | `wms_material`（WMS 物料主数据）FULL OUTER JOIN `wbs_zmmrp048_parsed`（ERP 需求计划 ZMMRP048） | ⚠️ 混合，ERP 优先 |
| `dim_project_cache`（项目维度） | `wbs_zmmrp226_parsed`（ERP 需求计划报表 ZMMRP226）FULL OUTER JOIN `wbs_zmmrp048_parsed`（ERP 需求计划 ZMMRP048） | ✅ 基本 ERP |
| `dim_outbound_log_cache`（出库日志） | `wms_inventory` ＋ `wms_inventory_log`（`change_type` 31拣货 / 34维修 / 35报废 / 36返修） | ❌ WMS |

> 上述维度缓存的刷新逻辑见 `backend/sql/03_dim_cache_tables.sql` 的 `fn_refresh_dim_caches()`。

### 结论：一个关键口径

- **数值类字段（金额 / 数量 / 库龄 / 日期）全部来自 WMS**（`wms_inventory` + `wms_inventory_log` + `wms_project_inventory`）。
- **维度类字段（项目名 / 采购人 / 联系人 / 提报人 / 部门 / 物料名）实际上来自 ERP 需求计划解析表**（`wbs_zmmrp226_parsed`、`wbs_zmmrp048_parsed`）。
- 所以本清单里「是否 ERP」列指的是 **该指标的「数值」来源**：K1/K2/K4 与领用率类指标直接查 ERP 表 `erp_catalog_mb51`，标 ✅；其余指标数值来自 WMS 视图，标 ❌——但它们的「项目 / 采购人」维度文字其实源自 ERP 需求计划。

## 一、例子拆解：`#/path1` 的「采购领用率（金额）」= 68.50%

| 项目 | 内容 |
|---|---|
| **前端取值** | `erpClaim.year.claim_rate_amount`（注意：用的是 **ERP 的当年值**，不是 WMS） |
| **后端函数** | `get_erp_claim_indicators()` → `_query_erp_claim_aggregates()` → `_build_erp_claim_metrics()`（`backend/erp_inventory.py`） |
| **数据来源表** | `public.erp_catalog_mb51`（ERP 物料凭证清单 MB51） |
| **计算过程** | 当年净入库 `net_inbound_year` = Σ `DMBTR`（`bwart IN ('101','102')` 且 `BLDAT` 前4位=当年）；当年出库 `outbound_year` = Σ `-DMBTR`（`bwart IN ('201','221','222','Z61','Z62')` 且当年）；**领用率 = outbound_year ÷ net_inbound_year × 100%** |
| **涉及字段** | `bwart`（移动类型）、`row_json->>'DMBTR'`（以本币计的金额）、`row_json->>'BLDAT'`（凭证日期，取前4位作年份） |
| **是否 ERP 数据** | ✅ 是（ERP） |

即：`68.50% = 当年出库金额 ÷ 当年净入库金额`，其中净入库 = 101收货 − 102冲销。

## 七、需要特别注意的三个口径陷阱

1. **「采购人」字段有 3 个含义**，不同接口指向不同字段：
   - `get_by_purchaser()` / K9 = `project_contact`（联系人）
   - `get_structure_indicators()` 的 `purchaser_ratios` = `purchaser_name`（申请人）
   - `_get_wide_structure_aggregates()` 的 K6 `purchaser_rows` = `project_contact`（联系人）；而 K6 前端表头又用 `project_submitter`（提报人）列展示

2. **「库存总额」有 WMS 与 ERP 两个口径**：`summary.total_inventory_amount`（WMS 当前实物库存）与 `erpClaim.erp_inventory`（ERP `v_batch_lifecycle.best_inventory_amt`（最佳估计库存金额），含 ERP-only 批次）。页面 2 的「5. 所有库存金额」用的是 ERP 口径，其余页面 KPI 卡用的是 WMS 口径。

3. **K1/K2/K4 前端有覆盖**：后端 `get_kpi_checklist()` 算的是 WMS 口径，但 `KpiChecklist/index.vue` 在 `coreKpiList`/`constraintKpiList` 里用 `getErpClaim()` 覆盖了 K1（ERP领用率）、K2（wmsSummary库存）、K4（ERP未领用），导致「显示值 ≠ 后端返回值」。
